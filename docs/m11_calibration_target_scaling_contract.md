# M11 Calibration + Target Scaling Contract

**Status**: Active  
**Created**: 2026-06-15  
**Depends on**: M10 Evaluation + Calibration Hardening  

---

## 1. Objective

M11 audits the target/output scale path and closes the calibration diagnosis from M10.

The goal is to answer, with reproducible reports:

1. Is there a target scale or inverse-transform bug?
2. Are model outputs in the same unit as realized targets?
3. Does post-hoc calibration materially improve quantile coverage?
4. Does the calibrated candidate beat rolling historical baselines?
5. Should the current champion be accepted, rejected, or re-tested?

AlphaTrade is still development-stage. M11 reports are evaluation and calibration diagnostics only, not trading-readiness claims.

M9/M10/M11 backtest outputs are lightweight evaluation handoff checks, not full execution simulators.

---

## 2. Inputs

M11 consumes the completed M10 reports, M9 test predictions, processed M1 bars/index files, and validation predictions for fitting post-hoc calibration.

| Input | Path | Contract |
|---|---|---|
| M10 prediction eval | `$M10_REPORTS/m10_prediction_eval_metrics.json` | Raw model test metrics |
| M10 baseline comparison | `$M10_REPORTS/m10_baseline_comparison.json` | Zero and rolling historical baselines |
| M10 eval rows | `$M10_REPORTS/m10_eval_rows.parquet` | Test predictions aligned with realized targets |
| M9 test predictions | `$M10_REPORTS/m9_predictions.parquet` | Stable M9 wide format |
| Validation predictions | `$REPORTS/m11_val_predictions_raw.parquet` | Raw model predictions on validation period |
| Processed bars/index | `data/processed/m1_f8/{symbol}/` | `bars.parquet` plus `index_train/val/test.parquet` |

Validation predictions are generated by M9 offline inference on a validation date range, then filtered to rows present in `index_val.parquet` before fitting calibration.

## 3. Target Scale Audit

M11 must trace the target path from data construction to inference and evaluation.

Required code path audit:

| Stage | File | Expected behavior |
|---|---|---|
| Target generation | `src/alphatrade/scripts/build_m1_sample_index_v2.py` | `y_h = log(close[t+h] / close[t])` |
| Training dataset | `src/alphatrade/window_cache.py` | `y_h*` copied directly into training `y` |
| Training loss | `src/alphatrade/scripts/train_m4_alphatrade.py` | Pinball loss compares raw `y` to `output.log_return_quantiles` |
| M9 inference | `src/alphatrade/inference.py` | Writes model output directly, no inverse transform |
| M10 evaluation | `src/alphatrade/scripts/build_m10_prediction_eval.py` | Realized target uses the same raw log-return formula |

Required audit conclusion fields:

- target unit
- target formula
- whether training target normalization exists
- whether inference inverse transform is required
- whether inference inverse transform is present
- whether engineering scale mismatch is found
- whether model output scale mismatch is found

The audit must compare, by horizon:

- train target distribution
- validation target distribution
- test target distribution
- raw model output distribution
- final M9 prediction distribution
- prediction q90/q10 width vs realized p99/p01 scale

## 4. Post-Hoc Calibration Diagnostic

M11 includes a calibration-only experiment. It must not retrain the model and must not use test data to fit calibration.

Calibration fitting rules:

| Rule | Contract |
|---|---|
| Fit split | validation only |
| Fit rows | filtered to `index_val.parquet` |
| Method | monotonic per-horizon quantile calibration |
| Current implementation | additive residual quantile shifts per horizon/quantile |
| Non-crossing | enforced after calibration |
| Test application | apply fitted calibration to M10 test rows |

The calibrated candidate is diagnostic only. It must not be promoted unless a later milestone adds a separate promotion gate.

## 6. Model Quality Validation

M11 model-quality validation uses severity labels:

- `PASS`
- `WARN`
- `FAIL_MODEL_QUALITY`

These labels are model-quality diagnostics, not schema failures.

Required checks:

| Check | Fail condition |
|---|---|
| model vs zero baseline pinball | model pinball worse than `zero_return_quantile` |
| model vs rolling baseline pinball | model pinball worse than `rolling_historical_quantile` |
| coverage MAE | coverage calibration MAE above `0.05` |
| IC materiality | max abs Pearson/rank IC below `0.005` |
| prediction interval scale | q90/q10 scale more than 10x realized p99/p01 scale |
| q50 coverage | any horizon q50 absolute coverage error above `0.20` |

A valid M11 closure may have:

```text
schema: ALL PASS
closure semantic: PASS
model-quality: FAIL_MODEL_QUALITY
```

This means reports are valid and the rejected-champion decision is internally consistent.

## 7. Closure Semantic Checks

`validate_reports_schema.py --profile m11 --strict` must run real M11 closure semantic checks.

Required closure checks:

| Check | Contract |
|---|---|
| `m11_closure_files_exist` | Required M11 JSON/Markdown closure reports exist |
| `m11_closure_files_load` | Required JSON files load successfully |
| `target_scale_bug_ruled_out` | Target unit is raw log return and no engineering scale mismatch is found |
| `output_calibration_problem_confirmed` | Model output scale/calibration problem is confirmed |
| `posthoc_calibration_improves_coverage` | Calibrated coverage MAE is materially lower than raw |
| `calibrated_model_still_loses_to_rolling_historical` | Calibrated pinball remains worse than rolling historical |
| `calibrated_candidate_not_promoted` | Calibrated candidate metadata says not promoted |
| `champion_remains_rejected` | Calibration and metadata agree champion is rejected |
| `m12_next_milestone_recorded` | Decision memo records M12 as next milestone |

Strict M11 validation passes when schema validation and closure semantic checks pass, even if model-quality status is `FAIL_MODEL_QUALITY`.

## 8. Calibrated Prediction Metadata

M11 must persist metadata for the calibrated candidate, but it must not promote it.

`m11_calibrated_prediction_metadata.json` records:

- raw model version
- calibrated candidate version
- prediction schema version
- horizons and quantiles
- whether calibrated predictions were written
- calibration method and fit rows
- validation split filter metadata
- raw/calibrated/rolling metric summary
- promotion decision

For M11 closure:

```text
calibrated_predictions_written = false
promoted = false
promotion_status = not_promoted
champion_status = rejected_pending_retrain_or_stronger_fix
```

## 9. Decision Memo

M11 must write:

```text
$REPORTS/M11_DECISION_MEMO.md
```

The memo must state:

1. target scale bug ruled out
2. output calibration problem confirmed
3. post-hoc calibration improves coverage
4. calibrated model still loses to rolling historical baseline
5. champion remains rejected
6. next milestone is M12 feature/label/baseline expansion

The memo is the human-readable closure artifact for review.

## 10. Reproduction

Use the CUDA environment:

```bash
export RUN="conda run -n alphatrade_cuda12 env -u LD_LIBRARY_PATH"
export M10_RUN_ROOT="$(pwd)/../alphatrade_runs/m10_evalcal_full_20260615_065041"
export M10_REPORTS="$M10_RUN_ROOT/reports"
export ALPHATRADE_RUNS_ROOT="$(pwd)/../alphatrade_runs/m11_calibration_$(date +%Y%m%d_%H%M%S)"
export REPORTS="$ALPHATRADE_RUNS_ROOT/reports"
```

Generate validation predictions:

```bash
$RUN python src/alphatrade/scripts/batch_infer_offline.py \
  --bundle "$M10_RUN_ROOT/artifacts/model_bundle/<model_version>" \
  --data-dir data/processed/m1_f8 \
  --symbols <comma-separated-symbols> \
  --start 2023-01-01 \
  --end 2023-12-31 \
  --output-root "$ALPHATRADE_RUNS_ROOT" \
  --output "$REPORTS/m11_val_predictions_raw.parquet" \
  --output-metrics "$REPORTS/m11_val_infer_metrics.json" \
  --output-metrics-md "$REPORTS/m11_val_infer_metrics.md" \
  --progress-log "$REPORTS/m11_val_infer_progress.jsonl" \
  --batch-size 2048
```

Build M11 audit/calibration reports:

```bash
$RUN python src/alphatrade/scripts/build_m11_scale_calibration_report.py \
  --m10-reports-dir "$M10_REPORTS" \
  --val-predictions "$REPORTS/m11_val_predictions_raw.parquet" \
  --data-dir data/processed/m1_f8 \
  --output-root "$ALPHATRADE_RUNS_ROOT"
```

Build closure metadata and decision memo:

```bash
$RUN python src/alphatrade/scripts/build_m11_closure.py \
  --output-root "$ALPHATRADE_RUNS_ROOT"
```

Validate M11:

```bash
$RUN python src/alphatrade/scripts/validate_reports_schema.py \
  --profile m11 \
  --strict \
  --output-root "$ALPHATRADE_RUNS_ROOT"
```

Run tests:

```bash
$RUN python -m pytest src/alphatrade/tests -q
```

## 11. Acceptance Checklist

M11 is accepted only when:

- [ ] target scale audit explains the mismatch or rules it out clearly.
- [ ] training, inference, and evaluation units are documented.
- [ ] M11 quality report separates schema status from model-quality status.
- [ ] post-hoc calibration is fit on validation data only.
- [ ] calibrated coverage MAE improves materially.
- [ ] calibrated model is re-compared against rolling historical baseline.
- [ ] calibrated candidate metadata is persisted.
- [ ] calibrated candidate is not promoted unless it satisfies a later promotion gate.
- [ ] `M11_DECISION_MEMO.md` records the closure decision.
- [ ] `validate_reports_schema.py --profile m11 --strict` passes.
- [ ] `python -m pytest src/alphatrade/tests -q` passes.
