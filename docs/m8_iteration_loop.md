# M8: Iteration Loop

The iteration loop is the stable workflow for running experiments, comparing against a baseline, and gating on quality. One command drives the full pipeline:

```
sweep → leaderboard → regression report → schema/semantic gate
```

## Quick Start

```bash
export ALPHATRADE_RUNS_ROOT="$(pwd)/../alphatrade_runs/m7_smoke"

# Full iteration (m7 ablation sweep)
conda run -n alphatrade_cuda12 env -u LD_LIBRARY_PATH \
  python src/alphatrade/scripts/run_iteration.py \
  --sweep-config configs/sweep/m7.yaml --profile m7 --smoke --resume --strict
```

## How It Works

`run_iteration.py` chains three existing scripts:

1. **`run_m5_sweep.py`** — trains and evaluates all (exp_id, seed) combos, builds leaderboard
2. **`build_m7_regression_report.py`** — compares each experiment against the baseline
3. **`validate_reports_schema.py`** — validates all reports against schemas and semantic checks

If any step fails, the pipeline stops and exits with a non-zero code.

## Baseline Freeze Policy

The baseline must be pinned to an **immutable reference** so that regression comparisons remain stable. The authoritative freeze record is `$ALPHATRADE_RUNS_ROOT/reports/m6_baseline_run.md` (generated by `gen_m6_baseline_report.py`), which captures:

- `git_sha` — the commit that produced the baseline
- `config_hash` — SHA256 of the training config (must match sweep manifest)
- `run_id` per seed — unique training run identifiers
- `dataset_config`, `universe`, `seeds` — full reproduction coordinates

**Rule:** changing `defaults:` in a sweep config changes `config_hash`, which means the baseline is no longer the same experiment. If you need to update defaults, you must create a new baseline version (see [Upgrading the Baseline](#upgrading-the-baseline-versioned-upgrade)).

## Artifacts (must exist after a successful run)

A successful `run_iteration.py` execution produces:

| Artifact | Path | Notes |
|----------|------|-------|
| Sweep manifest | `$ALPHATRADE_RUNS_ROOT/reports/m5_sweep_manifest.json` | All runs with run_id, config_hash, file paths |
| Leaderboard | `$ALPHATRADE_RUNS_ROOT/reports/m5_leaderboard.json` + `.md` | Ranked experiment summary |
| Regression report | `$ALPHATRADE_RUNS_ROOT/reports/m7_regression_report.json` + `.md` | Only when `--profile m7` |
| Gate output | `$ALPHATRADE_RUNS_ROOT/reports/<profile>_schema_validation.json` + `.md` | Schema + semantic validation |
| Per-run train metrics | `$ALPHATRADE_RUNS_ROOT/reports/m5_{exp_id}_seed{seed}_train_metrics.json` | One per (exp_id, seed) |
| Per-run eval metrics | `$ALPHATRADE_RUNS_ROOT/reports/m5_{exp_id}_seed{seed}_eval_metrics.json` | One per (exp_id, seed) |
| Per-run markdown | `$ALPHATRADE_RUNS_ROOT/reports/m5_{exp_id}_seed{seed}_{train,eval}_run.md` | Optional human-readable |

All of the above are validated by the gate step. Missing required files cause `--strict` to fail.

## Adding a New Experiment

1. Open your sweep config (e.g. `configs/sweep/m7.yaml`)
2. Add an entry under `experiments:`:

```yaml
experiments:
  - exp_id: baseline
    description: "Baseline (frozen from M6)"
    overrides: {}
  - exp_id: my_new_ablation
    description: "Ablation: describe what changed"
    overrides: {some_param: new_value}
```

3. Run the iteration:

```bash
conda run -n alphatrade_cuda12 env -u LD_LIBRARY_PATH \
  python src/alphatrade/scripts/run_iteration.py \
  --sweep-config configs/sweep/m7.yaml --profile m7 --resume --strict
```

No code changes needed — only YAML.

## Upgrading the Baseline (Versioned Upgrade)

Baseline upgrades are **versioned** — you never modify an existing baseline in-place.

**Prohibited:** changing `defaults:` in a sweep config that already has committed results under that `version`. This silently changes `config_hash`, making historical regression reports non-reproducible.

**Correct procedure:**

1. Bump the sweep config `version` (e.g. `m7_sweep_v1` → `m7_sweep_v2`)
2. Update `defaults:` to include the winning overrides
3. Set `baseline_exp_id` to the new baseline name (e.g. `baseline_v2`) or keep `baseline` if the version bump is sufficient to distinguish
4. Use a new `ALPHATRADE_RUNS_ROOT`, then re-run the **full** iteration **without** `--resume`
5. Re-generate the baseline freeze record (`gen_m6_baseline_report.py` or equivalent)
6. Commit the updated config/docs; keep generated outputs in `alphatrade_runs`

This ensures every past `version` + `config_hash` pair remains reproducible.

## CLI Reference

```
python src/alphatrade/scripts/run_iteration.py \
  --sweep-config <path>   # Required: sweep config YAML
  --profile <name>        # Required: validator profile (m5, m7, ...)
  [--output-root <path>]  # Optional: generated output root
  [--reports-dir <path>]  # Optional: explicit reports directory
  [--smoke]               # Smoke test mode (3 symbols, 3 steps)
  [--resume]              # Skip runs whose outputs already exist
  [--strict]              # Exit 1 on any required validation failure
  [--dry-run]             # Print sweep plan and exit
```

### `--resume` safety boundary

`--resume` skips a run if its output files (`m5_{exp_id}_seed{seed}_{train,eval}_metrics.json`) already exist and are valid JSON. It does **not** check whether the existing outputs match the current `config_hash`.

**Rule:** if you change `defaults:` or an experiment's `overrides:`, you **must** run without `--resume` (or delete stale output files) to ensure results reflect the new config. Using `--resume` after a config change will silently reuse stale results.

## Sweep Config Fields

| Field | Required | Description |
|-------|----------|-------------|
| `version` | yes | Config version identifier |
| `baseline_exp_id` | no | Experiment to use as regression baseline (default: `"baseline"`) |
| `expected_seeds` | yes | List of random seeds to run per experiment |
| `primary_metric` | yes | Metric used for leaderboard ranking |
| `dataset_config` | yes | Path to dataset config |
| `defaults` | yes | Default training hyperparameters |
| `experiments` | yes | List of experiments with `exp_id`, `description`, `overrides` |

## Branch Strategy

1. Create a feature branch from `main`
2. Add experiments to sweep config
3. Run iteration with `--smoke` first to verify plumbing
4. Run full iteration
5. Keep generated outputs in `alphatrade_runs`; commit only source/config/docs decisions

## Reproduction

```bash
export ALPHATRADE_RUNS_ROOT="$(pwd)/../alphatrade_runs/m7"

# Smoke test (fast, verifies plumbing)
conda run -n alphatrade_cuda12 env -u LD_LIBRARY_PATH \
  python src/alphatrade/scripts/run_iteration.py \
  --sweep-config configs/sweep/m7.yaml --profile m7 --smoke --resume --strict

# Full run (trains all experiments × seeds)
conda run -n alphatrade_cuda12 env -u LD_LIBRARY_PATH \
  python src/alphatrade/scripts/run_iteration.py \
  --sweep-config configs/sweep/m7.yaml --profile m7 --resume --strict

# Validate only (no training)
conda run -n alphatrade_cuda12 env -u LD_LIBRARY_PATH \
  python src/alphatrade/scripts/validate_reports_schema.py --profile m7 --strict
```
